# Live Azure validation — 2026-07-16

This baseline was deployed, assigned, exercised, remediated, and removed in a
disposable Microsoft-sponsored Azure subscription. Azure accepted all 15 custom
definitions and the initiative server-side before any resource test began.

## Scope and cost controls

- Test scope: one tagged resource group, isolated from the tenant's existing
  hybrid VPN resource group.
- Primary region: East US 2.
- VM: `Standard_D2als_v7` (2 vCPU, 4 GiB), 30 GiB Standard managed OS disk,
  private NIC, no VM public IP.
- VM runtime: 37 minutes. At the observed $0.0804/hour retail compute rate,
  compute was under $0.06 before disk and the short-lived standalone public-IP
  fixture.
- No SQL database, Recovery Services vault, backup data, paid monitoring
  ingestion, Azure OpenAI deployment, or Foundry deployment was created.
- The existing hybrid VPN resources were excluded from policy assignments and
  were not changed.

`Standard_D2s_v5` was initially selected but Azure marked it unavailable for
this subscription in East US 2. `Standard_D2als_v7` had no subscription or
regional restriction and ample regular-priority quota.

## Test results

| Control | Noncompliant path | Compliant/remediation path | Result |
|---|---|---|---|
| Storage HTTPS only | Explicit `supportsHttpsTrafficOnly=false` was denied with `RequestDisallowedByPolicy`. | HTTPS enabled succeeded. | Pass |
| Storage minimum TLS | A direct ARM PUT with `TLS1_0` was denied. The Azure CLI itself upgraded a requested TLS 1.0 account to TLS 1.2 and warned that TLS 1.0/1.1 were retired. | TLS 1.2 succeeded and reported compliant. | Pass |
| Storage public blob access | Explicit `allowBlobPublicAccess=true` was denied. | `false` succeeded and reported compliant. | Pass |
| NSG management ports | Internet-to-22 was denied. Before the fix, `::/0`-to-3389 succeeded; after the fix the same request was policy-denied. | Internet-to-443 succeeded. | Pass after fix |
| NIC public IP | Creating a NIC with the standalone test public IP was denied. | A private-only NIC succeeded. | Pass |
| SQL public access | A logical server with public access enabled was policy-denied. | Public access disabled passed policy evaluation, but the provider rejected new logical servers in both East US 2 and East US with `RegionDoesNotAllowProvisioning`; no SQL server or database remained. | Policy pass; provider capacity blocked provisioning |
| Key Vault purge protection | A vault without purge protection was denied. | Purge protection with the seven-day minimum retention succeeded. | Pass |
| Required RG tag | A missing tag was denied. An empty `CostCenter` initially succeeded, reproducing a defect; after the fix empty was denied and a non-empty value still succeeded. | Non-empty `CostCenter=PolicyTest` succeeded. | Pass after fix |
| Inherit RG tag | An empty resource tag reproduced the gap found in review. | New storage/NIC resources inherited the tag, an empty VNet tag was replaced, and remediation backfilled the workspace created before assignment. | Pass after fix |
| Allowed locations | An otherwise compliant West US 2 storage account was denied. | East US 2 resources succeeded. | Pass |
| Allowed VM SKUs | `Standard_D4als_v7` was denied before allocation. | `Standard_D2als_v7` succeeded. | Pass |
| VM backup audit | The unprotected VM reported `NonCompliant`. | A positive backup fixture was intentionally omitted because current vault soft-delete behavior would make teardown heavier; the audit detection path was the target of this control. | Pass for intended audit path |
| Managed disks | A crafted legacy VM PUT containing `osDisk.vhd.uri` was policy-denied. | The real VM used a managed disk and reported compliant. | Pass; control is legacy defense in depth |
| Key Vault diagnostics | An audit-logs-only setting with `AllMetrics=false` reproduced the old semantic gap. | The corrected DINE deployed audit logs plus `AllMetrics=true`. Disabling metrics again caused policy to repair the same setting back to enabled; the policy ARM deployment succeeded and final state was `Compliant`. | Pass after fix |
| VM system identity | The initial VM reported `NonCompliant` without an identity. | Adding `SystemAssigned` changed the policy state to `Compliant`. | Pass |

Every deny result named the expected custom policy definition and assignment.
The Azure CLI's known error-handling bug masked the top-level VM denial with
`The content for this response was already consumed`, but its traceback still
contained the complete `RequestDisallowedByPolicy` result and the expected
`allowed-vm-skus` reference ID.

## Improvements made from live evidence

1. Require non-empty RG tags and replace missing or empty resource tags while
   preserving non-empty resource-level overrides.
2. Add IPv6 Internet source `::/0` to both NSG source-prefix forms.
3. Require enabled `AllMetrics` in the Key Vault diagnostics existence check,
   evaluate after provisioning, remove the diagnostic resource's unnecessary
   location field, and surface workspace permission assignment metadata.
4. Match Azure's current VM-backup built-in exclusions for Databricks and Azure
   OpenShift-managed VMs.
5. Remove TLS 1.1 as an allowed policy floor after Azure's retirement warning;
   TLS 1.2 is now the only supported baseline floor.
6. Make assignment role grants idempotent and fail-closed, derive a default
   definition subscription from the assignment scope, and scope Log Analytics
   Contributor to the selected workspace.
7. Add `unassign.sh` and `undeploy.sh` so assignment identities, RBAC grants,
   initiatives, and definitions are removed in a safe order.

## Teardown verification

- Both test assignments and all remediation jobs were removed.
- The assignment identity's Contributor, Monitoring Contributor, and Log
  Analytics Contributor role assignments were removed before its assignment.
- The initiative and all 15 custom definitions were removed with
  `scripts/undeploy.sh`.
- Re-running both cleanup scripts against the clean subscription was a no-op
  and exited successfully.
- The Log Analytics workspace was force-deleted rather than left recoverable.
- The test resource group and all active resources were deleted.
- The purge-protected Key Vault remains visible only as Azure's unavoidable
  seven-day soft-deleted tombstone; it cannot be purged early and has no active
  resource or compute cost.
- Resource-provider registrations remain enabled. Registrations are
  subscription configuration, not billable resources.
